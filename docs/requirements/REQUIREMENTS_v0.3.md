## 目的と主ユースケース

本人が確認したゴールに対し、YouTube利用中の観測からAgentが行動の仮説を作り、必要な場合だけ「少し休みますか？」と提案する。目的から外れた事実、視聴、依存、後悔を断定しない。ユーザーは通常の利用中に同期/分析ボタンを押す必要がない。

1. 初回に対象YouTube、ゴール、収集同意、クラウド送信同意を確認する。
2. 「利用中の自動分析・提案」を説明し、本人が個別に有効化する。既存のクラウド同意を自動分析の同意とみなさない。
3. 普段どおりYouTubeを使う。端末が操作を取得し、開始条件に達すると現在の観測スナップショットを自動送信してAgentを起動する。
4. Agentがゴール/時系列/クリック/本人の過去回答を必要に応じて調べる。意味的なゴール乖離の可能性と有効な観測根拠がある場合だけ提案候補を返す。
5. 端末が最新性・対象アプリ・同意・頻度を確認してYouTube上にオーバーレイを表示する。
6. ユーザーが「10分休む」「このまま続ける」「目的に沿っている」「自動提案を停止」から選ぶ。「根拠を見る」も提供する。
7. 「10分休む」を選んだときだけ一時休止する。休止中のYouTube再起動には残時間/解除操作を表示し、本人が解除できる。期限到達時は自動解除する。

## 要件と受入条件

| 要件 | 仕様 | 受入 |
|---|---|---|
| RT-01 | 本人ゴールの確認/修正、収集・クラウド・自動分析の個別同意。権限だけで開始しない | RA-01: 未同意/権限不足/未ログインでは自動送信も提案も行わない |
| RT-02 | YouTube利用中の自動分析。新しい観測に対しイベント駆動で再評価。終了待ちは不要 | RA-02: アプリへ戻る/ボタンを押すことなくAgentが起動する |
| RT-03 | 不変の観測スナップショットを同期。終了済みセッションの旧同期契約とは分離 | RA-03: 元イベント不変、同一スナップショット再送は冪等、別所有者/旧削除世代拒否 |
| RT-04 | read-only Tool調査、根拠付き仮説、unknown。外れた可能性を提案条件として扱う | RA-04: 学習継続/意図的休憩/観測不能で不当な制限提案をしない。根拠IDが実在する |
| RT-05 | YouTube上のオーバーレイで休止/続行/訂正/停止/根拠を選べる | RA-05: 背景アプリやロック画面には出ず、表示で勝手に制限しない |
| RT-06 | 本人の選択に基づく10分の解除可能な休止。OSの強制停止/アンインストール/設定妨害は行わない | RA-06: 未承認では介入せず、明示選択で開始、期限/解除/機能停止で復帰 |
| RT-07 | 続行・訂正・休止・解除の選択を区別して記録。操作は観測を書き換えない | RA-07: 本人回答だけ保存、未回答は未回答、再起動/撤回/アカウント変更で古い提案を無効化 |
| RT-08 | 分析/通知の頻度、同時実行、遅延結果、通信失敗を制御 | RA-08: 通知連発/無制限推論/古い文脈への提案なし。失敗時は通常利用継続 |
| RT-09 | 実機で自動監視→分析→提案→本人承認→休止→解除を確認 | RA-09: Pixel実機によるE2E証拠。架空ケースと実観測を混同しない |

## 自動開始と提案の初期パラメータ

- 開始前提: 本人確認済みゴール、収集/クラウド/自動分析の全同意、Firebaseログイン、必要OS権限、YouTube前面、画面ON/ロック解除。認証UI/入力欄は収集対象外。
- YouTube利用開始から60秒後に初回分析し、利用中は60秒ごとに新しいスナップショットで分析する。クリック件数や新しいクリックを開始条件にしない。再生中でクリックが増えなくても実行し、観測不足ならunknownと扱う。
- 端末の推論開始間隔は60秒以上、最大60回/直近1時間、同時実行1件。前回が実行中ならその回をスキップし、完了後にまとめて実行しない。通信失敗も開始回数に含め、自動即時リトライしない。サーバー側の本人別上限も必須。
- 直近最大100観測、総量300KB以内のスナップショット。イベントID/時刻/状態を保持。保持期間は端末7日、クラウドスナップショット24時間。期限切れをTool対象としない。
- 提案条件: 検証済みpossibly_diverged、観測不足でない、有効なクリック根拠が存在、最新のクリック文脈と一致。unknown/aligned/失敗では表示しない。
- 結果は観測スナップショット作成から60秒以内のみ利用。解析中に別クリック、YouTube離脱、画面ロック、同意変更、アカウント変更、削除世代変更があれば古い結果を提案に使わない。
- 通知クールダウンは10分。続行/閉じるも同じ間隔を適用。同一スナップショットの再提示はしない。本人による「目的に沿っている」をAIが上書きしない。
- 60秒周期は2026-10-11の本人指示による。YouTube離脱/ロック/同意撤回では停止する。実機で欠損率/遅延/費用を測り、周期を変更する場合は本人指示と変更記録を反映する。

## Agentと端末の役割

端末は観測と起動条件を監視する。Agentはスナップショット単位に起動し「Toolを選ぶ→結果を読む→必要なら追加Tool→仮説を出す」を行う。常時動作する無期限のLLMループではない。既存ADKの調査Agent→提示Agent、45秒/モデル8回/Tool12回上限を維持する。

分析出力と介入を分離する。モデルがTool経由でゴール変更や制限を実行することは禁止。端末の決定的なPolicyが提示可否を判断し、制限開始は本人の選択を必要とする。時間差だけで目的乖離や視聴を推定しない。

## データ・状態契約

スナップショットはsnapshot_id、owner（認証から決定）、session_id、consent_revision、goal_revision、削除generation、作成時刻、文脈sequence、eventsを紐付ける。同じsnapshot_idは不変で、増分観測には新しいIDを使う。旧sessions:batchの凍結済み送信を上書きしない。本人確認済みゴールもスナップショット時点で固定する。

分析は対象snapshot_id/ゴールrevision/削除generationを返し、端末が現在状態と照合する。休止は対象アプリ・承認時刻・期限・本人の解除をローカルに記録。再起動後の期限判定、時計変更、権限失効、サービス再接続を検証する。実観測はreal、架空試験はsample。サンプル分析で通常利用に制限をかけない。

## Android方針と失敗時

オーバーレイ候補はAccessibilityServiceのTYPE_ACCESSIBILITY_OVERLAY。明示選択後のHOME操作と解除可能な休止画面を用いたアプリ内の休止機構を実機で検証する。OS全体でYouTubeを起動不能にする保証はしない。SDK権限で実装可能なこととストア配布審査を区別する。[Android公式AccessibilityService](https://developer.android.com/reference/android/accessibilityservice/AccessibilityService)、[公式オーバーレイ実装例](https://codelabs.developers.google.com/codelabs/developing-android-a11y-service/)を参照。

オーバーレイ非対応/権限不足は設定画面に状態を表示する。通常通知で代替できてもRA-05実機オーバーレイ合格とは扱わない。timeout/モデル出力不正/オフライン/上限到達では勝手に制限せず、状態のみ記録。サービス停止やログアウト時には表示を消し、保留処理を無効化する。

## 対象外と現在の到達点

Webデモ、複数アプリ、自律的なゴール更新、本人承認なしの遮断、実際の閲読/視聴の断定は対象外。v0.2の収集・手動同期・分析・根拠・本人訂正は開発/振り返りの補助導線として保持する。

2026-10-11時点で実機収集/手動同期/分析/根拠表示を確認済み。自動実行・利用中スナップショット・オーバーレイ・休止は未実装。本書の完成をプロダクトの完成とは扱わない。

## Agent状態アイコン（2026-10-11本人追加指示）
- Agent有効時、YouTube上に小さなオーバーレイアイコンと「待機中」「判定中」を表示する。判定中は実際の自動分析リクエストの開始から終了/失敗までに限定する。
- タップで状態説明/設定/Agent OFFを提供。入力欄/機密UI、画面ロック、YouTube離脱、撤回、ログアウトでは非表示にする。動画の操作領域全体を遮断しない。
- 自動分析のruntime未接続時は詳細に開発中と明示し、判定中を模擬表示しない。DG-304でUI、DG-303で実分析への状態接続、DG-308で実機検証。
