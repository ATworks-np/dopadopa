# DopaGuard 要件定義 v0.3

2026-10-12に実装コードを照合し、この節を現行仕様とする。下の日付付き要求のうち、分析周期の固定、提案ボタン、即時解除、状態アイコンの文字、モデル45秒と矛盾するものは履歴である。

## 現行仕様（2026-10-12 コード照合）

### 画面と有効化

ホーム・操作履歴・設定の3画面。初回と変更は「学習・スキルアップ」「情報収集」「趣味・娯楽」「休憩・気分転換」「長時間利用を減らす」から1つ以上選んで保存する。目標設定にログインやAI送信は不要。

ホームの状態は「DopaGuard 有効中」または「DopaGuard 無効」で、トグルが自動分析の同意を切り替える。オンにするには、端末内収集の同意、クラウド送信の同意、ログイン、利用状況アクセス、ユーザー補助が揃っている必要がある。オフにするとYouTube上の見守りは止まる。収集やクラウド同意をオフにすると自動分析もオフになる。

設定は「分析の間隔」「提案通知の間隔」「データと同意」の3枚。データと同意には、ユーザー補助と利用状況アクセスのチェック（OS上で有効ならチェック、行を開くとOS設定）、収集同意、クラウド同意、ログイン、ログアウト、同意の撤回、データを削除して初期化がある。権限があっても同意をオンにするまで収集は始まらない。提案カードと休止画面は端末のライト/ダークに追従する。アプリ本体も追従する。

### 分析の間隔と即時実行

分析の間隔は1〜20分、1分刻み、初期値1分。YouTube利用を始めてからその間隔のあと初回、以後その間隔ごと。間隔を変えても進行中の分析は取り消さない。取りこぼした回はまとめ送りしない。実行中の回はスキップする。提案通知の間隔は別で、1〜20分、初期値10分。休止の長さは10分で固定。

状態オーバーレイの「今すぐ分析」は、利用開始から1分経つのを待たずに1回実行できる。直前の開始から60秒未満、または直近1時間に60回に達している場合は開始しない。自動の次の回は、設定した間隔だけ後ろへずれる。

開始の前提は、確認済みの使い方、収集/クラウド/自動分析の同意、ログイン、必要なOS権限、YouTubeが前面、画面オンである。スナップショットは最大100件。作成から60秒より古いスナップショットは分析を受け付けない。新クリックや間隔の経過だけでは結果を捨てない。同意撤回、ログアウト、使い方の変更、YouTube離脱、ロック、機密UIでは止める。

### 状態オーバーレイ

YouTube上のマークは文字もキャラもなく、光の粒子だけである。待機中は粒子がゆっくり漂い、分析中は中心へ寄って回る。枠は付けない。タップで詳細（今すぐ分析、設定を開く、AgentをOFFにする）を開く。長押しで画面内を移動でき、離した位置を覚える。入力欄、機密UI、ロック、YouTube離脱、撤回、ログアウトでは隠す。

### 提案と休止

提案は画面下部のカードで、「続ける」と「休む」だけ。理由を見るは選択とは別の開閉で、開いても休止は始まらない。カードはライト/ダークに追従する。提案が出るのは、検証済みの possibly_diverged、または usage_pattern=possible_chaining で、提案文と理由があるとき。unknown、alignedのみ、失敗では出さない。

休むを選ぶと10分の休止が始まり、再生の一時停止を試み、休止画面をYouTubeの上に全画面で残す。この時点ではホームへ戻さない。休止画面に出すのは、残り時間を囲む円と「ホームへ戻る」だけである。即時解除ボタンはない。ホームへ戻るを押したときだけホームへ移し、再生の一時停止と、出たピクチャーインピクチャーを閉じることを試みる。10分が過ぎるか、同意撤回、文脈の変化、サービスの再接続で休止は終わる。

### エージェントの判断

1つのエージェントがTool調査から判断まで行う。モデル期限は90秒、モデル呼び出し8回、Tool12回。Engineの作業待ちは100秒、APIへの接続20秒・読取110秒、APIリクエスト上限120秒、端末の分析読取130秒。必須Toolは get_user_goals、get_timeline、get_content_events。get_past_feedback は任意。

判断は二軸である。ゴールとの一致は aligned / possibly_diverged / unknown。使えるのは available のクリック文言と、WINDOW_CHANGE の表示タイトルだけである。経過時間、スクロール、クリックがないこと、missing、redacted はどちら側の根拠にもしない。inferred だけなら possibly_diverged にしない。同じ目的の深掘りは aligned。使い方に含まれない別目的を、直接クリックか表示タイトルが示すときだけ possibly_diverged。材料が足りなければ unknown とし、segments と transitions は空。

usage_pattern は possible_chaining / no_clear_chaining / unknown。ゴールに沿っていても、3つ以上の異なる取得済みコンテンツの移動が連鎖を支持するなら休止を提案できる。3件あるだけでは連鎖にしない。連鎖だけを理由に goal_alignment を possibly_diverged にしない。視聴、視線、依存、後悔は断定しない。ゴールの書き換えと本人訂正の自動作成はしない。

## 目的と主ユースケース

本人が確認したゴールに対し、YouTube利用中の観測からAgentが行動の仮説を作り、必要な場合だけ「少し休みますか？」と提案する。目的から外れた事実、視聴、依存、後悔を断定しない。ユーザーは通常の利用中に同期/分析ボタンを押す必要がない。

1. 初回に対象YouTube、ゴール、収集同意、クラウド送信同意を確認する。
2. 「利用中の自動分析・提案」を説明し、本人が個別に有効化する。既存のクラウド同意を自動分析の同意とみなさない。
3. 普段どおりYouTubeを使う。端末が操作を取得し、開始条件に達すると現在の観測スナップショットを自動送信してAgentを起動する。
4. Agentがゴール/時系列/クリック/本人の過去回答を必要に応じて調べる。意味的なゴール乖離の可能性と有効な観測根拠がある場合だけ提案候補を返す。
5. 端末が最新性・対象アプリ・同意・頻度を確認してYouTube上にオーバーレイを表示する。
6. ユーザーが「続ける」「休む」から選ぶ。「理由を見る」は選択と独立して開閉する。
7. 「休む」を選んだときだけ10分休止する。休止画面は全画面で残り時間とホームへ戻るだけを出し、即時解除はしない。期限到達時は自動解除する。

## 自動開始と提案の初期パラメータ

- 開始前提: 本人確認済みゴール、収集/クラウド/自動分析の全同意、Firebaseログイン、必要OS権限、YouTube前面、画面ON/ロック解除。認証UI/入力欄は収集対象外。
- 分析間隔は本人設定の1〜20分（初期値1分）。利用開始からその間隔後に初回分析し、以後その間隔で新しいスナップショットを分析する。クリック件数や新しいクリックを開始条件にしない。再生中でクリックが増えなくても実行し、観測不足ならunknownと扱う。オーバーレイの今すぐ分析は開始1分を待たないが、直前から60秒未満と1時間60回の上限は守る。
- 自動開始の最短間隔は設定値、最大60回/直近1時間、同時実行1件。前回が実行中ならその回をスキップし、完了後にまとめて実行しない。通信失敗も開始回数に含め、自動即時リトライしない。サーバー側の本人別上限も必須。
- 直近最大100観測、総量300KB以内のスナップショット。イベントID/時刻/状態を保持。保持期間は端末7日、クラウドスナップショット24時間。期限切れをTool対象としない。
- 提案条件: 検証済みpossibly_diverged、観測不足でない、有効なクリック根拠が存在、最新のクリック文脈と一致。unknown/aligned/失敗では表示しない。
- 結果は観測スナップショット作成から60秒以内のみ利用。解析中に別クリック、YouTube離脱、画面ロック、同意変更、アカウント変更、削除世代変更があれば古い結果を提案に使わない。
- 提案通知の間隔は本人設定の1〜20分、初期値10分。分析間隔および10分休止とは別。同一スナップショットの再提示はしない。本人の使い方をAIが上書きしない。
- 初期の分析間隔1分は2026-10-11の本人指示が起点で、2026-10-12に1〜20分の本人設定へ広げた。YouTube離脱/ロック/同意撤回では停止する。

## Agentと端末の役割

端末は観測と起動条件を監視する。Agentはスナップショット単位に起動し「Toolを選ぶ→結果を読む→必要なら追加Tool→仮説を出す」を行う。常時動作する無期限のLLMループではない。1つのエージェントが調査から判断まで行い、モデル90秒/モデル8回/Tool12回を上限とする。Engine作業100秒、API読取110秒、APIリクエスト120秒、端末の分析読取130秒。

分析出力と介入を分離する。モデルがTool経由でゴール変更や制限を実行することは禁止。端末の決定的なPolicyが提示可否を判断し、制限開始は本人の選択を必要とする。時間差だけで目的乖離や視聴を推定しない。

## データ・状態契約

スナップショットはsnapshot_id、owner（認証から決定）、session_id、consent_revision、goal_revision、削除generation、作成時刻、文脈sequence、eventsを紐付ける。同じsnapshot_idは不変で、増分観測には新しいIDを使う。旧sessions:batchの凍結済み送信を上書きしない。本人確認済みゴールもスナップショット時点で固定する。

分析は対象snapshot_id/ゴールrevision/削除generationを返し、端末が現在状態と照合する。休止は対象アプリ・承認時刻・期限・本人の解除をローカルに記録。再起動後の期限判定、時計変更、権限失効、サービス再接続を検証する。実観測はreal、架空試験はsample。サンプル分析で通常利用に制限をかけない。

## Android方針と失敗時

オーバーレイ候補はAccessibilityServiceのTYPE_ACCESSIBILITY_OVERLAY。明示選択後のHOME操作と解除可能な休止画面を用いたアプリ内の休止機構を実機で検証する。OS全体でYouTubeを起動不能にする保証はしない。SDK権限で実装可能なこととストア配布審査を区別する。[Android公式AccessibilityService](https://developer.android.com/reference/android/accessibilityservice/AccessibilityService)、[公式オーバーレイ実装例](https://codelabs.developers.google.com/codelabs/developing-android-a11y-service/)を参照。

オーバーレイ非対応/権限不足は設定画面に状態を表示する。通常通知で代替できてもRA-05実機オーバーレイ合格とは扱わない。timeout/モデル出力不正/オフライン/上限到達では勝手に制限せず、状態のみ記録。サービス停止やログアウト時には表示を消し、保留処理を無効化する。

## 2026-10-12 コンテンツ移動の連鎖検知（DG-303）
本人指示で、ゴールとの一致と、ついつい次の関連コンテンツへ移る連鎖の可能性を独立に調べる。内容が学習/情報収集/娯楽のゴールに合う場合でも、複数の具体的な表示タイトルと操作時系列が連鎖を支持するなら休止を提案する。goal_alignmentは内容と本人ゴールの対応のまま、usage_pattern=possible_chaining/no_clear_chaining/unknownとusage_pattern_evidence_idsを追加。連鎖根拠は少なくとも3つの異なる取得済みコンテンツ、最大10件。同じタイトルのCLICK/WINDOW_CHANGEを二重計数しない。
