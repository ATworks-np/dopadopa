# DopaGuard 開発エージェント指示書

本ファイルはコーディングエージェントに対するプロジェクト内の**作業手順**。作業前に `README.md`、`process/DEVELOPMENT_PROCESS.md`、`requirements/TRACEABILITY.md` と対象チケットを読む。

## 共通ルール

1. 1回の作業につき原則 **1チケット**。作業開始時に `python docs/scripts/tickets.py move <ID> in-progress --owner ...` を実行し、完了まで当該IDをPR/コミットに紐付ける。
2. **現行正本は requirements/REQUIREMENTS_v0.3.md。** 2026-10-11ユーザー指示で利用中の自動分析・オーバーレイ提案・本人承認による解除可能な休止をP0へ変更した。旧v0.2 DOCXは履歴。未承認の制限やP2の学習を勝手に実装しない。
3. YouTubeは**選択UIのみ限定**。`app_id` / `package_name` をイベント全体のスキーマから消さない。YouTube固有の処理はAdapter層へ閉じ込める。
4. Android Accessibilityで取得不能な文字列を推測して「取得した事実」として記録しない。`text_status: missing|redacted` と `observability` を使用する。
5. クリック文言や検索語、機密テキストはセンシティブな情報となる。**明示的同意のないクラウド送信は禁止**。入力欄・認証・DM等は除外し、ログにも残さない。解析するテキストは必要最小限。
6. Geminiの出力は**仮説**。後悔・依存・実際の閲読/注視や「無意識」を断定しない。`evidence_ids`、`uncertainty`、`unknown` を必須とする。
7. GeminiがToolを呼べる範囲は認可済みユーザー・セッションのみ。引数検証、返却サイズ、呼び出し回数、タイムアウトを制限。書込系Toolは本人の操作または明示的許可に限定する。
8. **本人承認なしの強制ブロックは禁止**。v0.3の本人選択による10分休止・即時解除を実装対象に含む。Accessibility利用の配布審査への適合を証明したものとして扱わない。
9. サンプルログと実機ログは混同しない。デモUIに `sample` / `real` を明示し、未検証の成功を報告しない。
10. ソース/テスト/ドキュメント変更後にテストを実施し、結果をチケット `## 検証記録` に追記する。チェックボックスが未完のチケットを `done` に移動しない。

## 標準ワークフロー

```
確認（依存／要件／リスク）
  → in-progress
  → 実装（小さな差分）
  → ローカルテスト・取得ログの検証
  → review（自己レビュー/他者レビュー）
  → done（証拠を記録、受け入れ条件チェック完了）
```

## 各ターンの終了時に必ず残すもの

- 更新したチケットと状態
- 変更ファイル、実行したコマンドと結果
- 未解決事項（理由/再現手順/次の一手）
- 実ログを扱ったか（サンプルのみか）

## 失敗時

- 特にUIテキストが取得できない場合、サンプルデータで**取れたことにしない**。画面/イベント種類、取得可否、取得不能理由を記録し、`blocked` にする。
- 結論が変わる技術・仕様変更は `process/RISKS_AND_DECISIONS.md` にADR形式で記録する。
- 依存完了前の作業が必要なら理由を明記して、最小範囲にとどめる。
