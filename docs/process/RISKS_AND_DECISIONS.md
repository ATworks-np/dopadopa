# リスク・意思決定ログ（ADR）

## ADR: 2026-10-12 DG-309 判断説明の本人表示
- 本人要求により、固定診断ログに加えTool操作と仮説・観測根拠・不確実性を詳細表示する。既存の検証済み分析結果を利用し、追加モデル呼出や新しいクラウド送信は行わない。
- 原文は本人の詳細UIにのみ表示。redactedは表示せず、missingは推測しない。説明はメモリ内に限り文脈変更/サービス破棄で消去する。診断ログは従来の固定語のみ。
- 表示は先頭6仮説/各4根拠、直近8回に制限。すべてのモデル呼出内部思考を保存する機能ではない。unknown/失敗/破棄の理由を創作しない。
- 本人が今回はコード・ビルドまでを指定したため、実機インストールは行わず表示受入は再開後に確認する。

## ADR: 2026-10-11 利用中の自動提案をMVPの中心へ変更

- 根拠: 本チャットでユーザーがYouTube利用中のAgent監視/overlay制限提案を明示し、要件再設計/チケット作成/開発開始を指示。
- 決定: REQUIREMENTS_v0.3.mdを現行正本とする。旧v0.2の事後手動分析/P1通知を、自動起動・提案・本人承認による休止を含むP0へ変更。DG-300〜308で開発する。
- 初期値: 推論30秒間隔/20回毎時/同時1件、通知10分間隔、結果鮮度60秒、本人選択による10分休止/即時解除。実機検証後に根拠付きで改訂する。
- 移行: 既存クラウド同意を自動分析同意とみなさず新opt-inを設ける。終了済み不変セッション同期と利用中snapshotを分離する。

- 実装状況: 実機手動分析は確認済み。自動実行・overlay・休止は未完成。

### ADR-20261011-04: 削除と実行中分析の競合
- 状況: 本人が削除した後、実行中の分析が結果を再保存し得た。
- 決定: owner単位のgeneration/deletingを使い、Firestore書込トランザクション内で削除状態と処理開始時generationを検証する。
- 削除中は別インスタンスの書込も拒否。削除失敗は書込停止を維持し、明示的な再削除を許可する。並行削除は拒否する。
- 証拠: MemoryStore/APIの競合再現テストを含む24件PASS。実Firestoreトランザクションは未検証。
- 影響: DG-009。Agent Engine採用時にもAPI保存時の同じ境界が必要。

### ADR-20261011-01: 実機待ちの独立実装
- 状況: ADBに本人の実機なし。携帯AVDもイメージ不足。Android35タブレットAVDでDB/画面試験は可能。
- 決定: DG-001はblocked。実機受入は未達のまま、確定したデータ契約と模擬応答による独立コード準備を進める。
- 理由: 実機取得の成功を捏造せず、端末接続後にすぐ照合できるようにする。
- 影響: DG-005/006/007とDG-009/010/011を依存未達時はforceでin-progress。理由は各チケットに記録。doneの依存条件は緩めない。
- 検証: 実機AC-02/03、Gemini実Tool Calling AC-04、Cloud Run AC-07は別証拠を取得する。

### ADR-20261011-02: スパイクと本実装の境界
- 決定: DG-001のJSONLは一時的な実機取得スパイク。正式本実装はRoom。親文脈抽出は実機照合まで無効。
- 理由: 未検証の親ノード文字列を動画タイトルとして扱わない。

### ADR-20261011-03: クラウド構成
- 決定: FastAPI/Pydantic、Firestoreの所有者別subcollection、Firebase ID token、google-genaiの明示read-only Toolループ。
- 理由: 観測契約と認可をサーバーで検証し、Agentに書込権限を与えない。
- 未決: 利用Google Cloudプロジェクト/Firebaseアプリ、Geminiモデル・実接続、削除と分析の競合、保持期間、同期と頻度制限。
- 検証: MemoryStore/FakeClientはローカル制御テストのみ。実サービスでの成功とは扱わない。

### ADR-20261011-04: Vertex用schemaと最終検証の分離
- 状況: 実Gemini検証でSDKがboolean Literalを拒否し、詳細なJSON Schema制約を送った要求も400となった。
- 決定: ProviderAnalysisはVertexに渡すboolean/基本schemaを生成。モデルの結果は元のAnalysisで厳密に再検証し、本人確認true・長さ/件数・余分なfield禁止・実在根拠・欠損を維持する。
- 理由: Providerのschema対応範囲に合わせながら、受入契約を緩めない。構造化出力段階にはTool履歴を再送せず、前段の調査結果を明示入力する。
- 検証: 実Vertex/ADKの架空3件completedとサーバー30件PASS。実機・Cloud Run経由の分析は別検証。

## DG-008: クラウド削除の復帰と世代隔離
- deletingだけの状態はプロセス中断で永久に残る可能性がある。120秒leaseを導入し、期限切れ後の本人削除再試行を許可する。
- 各文書削除はowner世代チェックとlease更新を同一transactionで行う。引継ぎ前のworkerは新世代を削除できず、失敗状態の更新も自分の世代だけに限定する。
- 個人内容を除くowner世代tombstoneは、旧要求の復活防止のため保持する。中断復帰は本人による削除再試行で実行し、バックグラウンドの自動復帰は未実装。

## DG-017: Android分析待機とサーバー上限
- Androidの分析read timeout55秒がCloud Run request timeout60秒より短く、55.545秒の応答を受け取れなかった。分析のみ65秒へ変更し、サーバー応答のため5秒の余裕を設ける。通常要求15秒、connect10秒、同意撤回時の接続キャンセルは維持する。
- Engine transportの55秒タイムアウト自体は別問題であり、この変更では解消したと判断しない。モデル実行45秒制限も変更しない。
- 実機保留・エミュレータ不使用のため、端末上の解消確認は未実施。端末なしのビルド/単体検証と、残課題の記録を行う。

## ADR: YouTube利用中の60秒周期（2026-10-11）
本人指示「youtube利用1分おきにagent loopして」に従い、30秒/2クリック/新クリック条件を撤廃。初回60秒、以後60秒間隔、60回/直近1時間へ変更。無操作の再生中も観測スナップショットから分析し、不足時unknown。実行中の周期はスキップし、後追い一括実行なし。提案の根拠/鮮度/10分cooldown/本人承認は継続。DG-301を再開、DG-302予算とDG-303 runtime契約を整合する。

## ADR 2026-10-12: 本人承認休止の時計と再接続

DG-304/305/307: 休止は本人ボタンだけで承認しelapsedRealtimeの10分期限を用いる。HOME失敗・期限・撤回・owner/ゴール変更・サービス停止/再接続で解除する。プロセス再起動時は残時間を復元せず解除し、期限不明の制限を残さない。要件の残時間復元ACは未達として保持。選択/終了は固定語の端末内履歴50件のみ、原文とAI説明は保存しない。cooldownは壁時計で永続化、時計逆行で新しい10分に置換。実機受入は未実施。

## 2026-10-12 DG-303: 結果破棄・振り返り廃止

本人指定により、新クリック・60秒経過で結果を捨てる処理を廃止。分析中も操作が続く通常利用で判断が出なくなるため、snapshotへの回答を受け取る。提案は取得済み観測に対する仮説であり、その後のクリックを分析済みとは扱わない。文脈終了/同意撤回/owner変更は取消し、認証と根拠検証は保持。分析タブと手動同期を削除。端末操作履歴は残す。

## ADR 2026-10-12: クリック通知に依存しないコンテンツ観測

本人指定で、動画を開いた後のAccessibilityタイトルの変化をWINDOW_CHANGEとして扱う。クリック通知がなくても画面内容変更から公開タイトルを読む。操作の因果関係/実際の注視は断定せずparent_context/inferredで保存する。YouTubeの表示直後のTextViewと、その後の仮想Buttonに対応。プレーヤー直下へ限定し、評価数・おすすめカード説明・ミニプレーヤーを除外する。同一タイトルの更新は記録しないため同名コンテンツ間の移動は区別不能。OCRは採用しない。

## ADR 2026-10-12: 目標設定の簡略化（DG-314）
本人指示により対話型の目標決定を廃止し、初回/変更とも5項目の複数選択と明示保存にする。目標設定のAI相談・認証依存をなくす。既存目標は本人保存まで保持、分析用description/revisionと個別同意は維持。

## ADR 2026-10-12: 表示コンテンツ根拠と単一Agent
本人指示により、CLICKだけでなくWINDOW_CHANGEの取得済みタイトルも行動理解の根拠にする。get_content_eventsを公開しsource/observabilityを保持。表示事実をクリック/視聴に置換しない。ADKは1つのLlmAgentへ統合し、Tool調査から構造化出力まで担当する。認可と根拠Validatorはエージェント外で維持する。

## ADR 2026-10-12: 検証エラーを同じAgentへ返す（DG-303）
本人指示により、回答の形式・ID・観測根拠・必須Toolの検証失敗は、その理由と不正な回答を同じ一時ADKセッションへ返して修正させる。初回に加えて最大2回の修正。全体45秒・8モデル呼出・12Toolの上限は修正を含めて共有する。通過した回答だけを返し、根拠捏造やunknown条件を緩めない。認可/削除/Tool実行失敗や通信失敗はこの修正の対象にしない。ADKのoutput_keyによる自動検証は原文付き例外をログへ出すため使わず、response schemaを維持したままアプリ側で検証する。修正用回答はメモリ内のみ、最大20000文字。診断にモデル回答・観測原文を保存しない。

## 2026-10-12 コンテンツ移動の連鎖検知（DG-303）
本人指示で、ゴールとの一致と、ついつい次の関連コンテンツへ移る連鎖の可能性を独立に調べる。内容が学習/情報収集/娯楽のゴールに合う場合でも、複数の具体的な表示タイトルと操作時系列が連鎖を支持するなら休止を提案する。goal_alignmentは内容と本人ゴールの対応のまま、usage_pattern=possible_chaining/no_clear_chaining/unknownとusage_pattern_evidence_idsを追加。連鎖根拠は少なくとも3つの異なる取得済みコンテンツ、最大10件。同じタイトルのCLICK/WINDOW_CHANGEを二重計数しない。
時間だけ/SCROLLだけ/単発/文字欠損は連鎖の根拠にしない。時刻は具体的なコンテンツ切り替え頻度の補助として使う。系統立った講義/目的のある比較や深掘りとの区別を検討する。関連動画リンクを経由したか/自動再生/実際の視聴/本人の無意識や依存は未観測であり断定しない。「ドパガキ」という呼称を本人へ表示しない。本人への提案は続ける/休むで承認を委ねる。
